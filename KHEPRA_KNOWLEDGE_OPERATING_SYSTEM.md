Le Knowledge Operating System (KOS) est le protocole d'exécution qui transforme l'écosystème documentaire KHEPRA en un système vivant d'amélioration continue. Là où la Constitution définit ce que KHEPRA est, là où le Governance définit comment les modules s'articulent, le KOS définit **comment chaque mission, interaction et production enrichit concrètement le patrimoine intellectuel du cabinet**.

Le KOS n'est pas un document de plus — c'est la discipline opérationnelle qui garantit que KHEPRA EXPERTS ne se contente jamais de produire un livrable, mais génère systématiquement de la connaissance réutilisable.

### Étape 1 — RAG (KHEPRA Regulatory RAG)

**Source de vérité réglementaire. Point d'entrée obligatoire de toute production.**

- Consultation des 15 bibliothèques réglementaires
- Requête des textes applicables (juridiction, domaine, date, statut)
- Vérification : texte en vigueur ou abrogé ?
- Identification des références croisées entre textes

**Document maître** : [KHEPRA_RAG_REGULATOIRE.md](./KHEPRA_RAG_REGULATOIRE.md)

```
INPUT  → Question / Demande / Mission
QUERY  → KHEPRA-RAG-v1/{bibliothèque}
OUTPUT → Textes applicables identifiés, sourcés, datés, statut vérifié
```

### Étape 2 — Méthodologies

**Savoir-faire KHEPRA. Comment aborder chaque type de mission.**

- Sélection de la méthodologie adaptée au type de mission
- Chargement des référentiels, grilles d'évaluation, protocoles
- Consultation des retours d'expérience sur des missions similaires
- Consultation de la Risk Library pour le secteur concerné

**Documents maîtres** : [KHEPRA_DELIVERABLE_FACTORY.md](./KHEPRA_DELIVERABLE_FACTORY.md), [KHEPRA_RISK_LIBRARY.md](./KHEPRA_RISK_LIBRARY.md), [KHEPRA_REGULATOR_EXPECTATIONS.md](./KHEPRA_REGULATOR_EXPECTATIONS.md)

```
INPUT  → Textes applicables (étape 1)
QUERY  → Méthodologies KHEPRA + Risk Library + Regulator Expectations
OUTPUT → Approche méthodologique validée, grilles, risques sectoriels connus
```

### Étape 3 — Templates

**Standardisation. Ne jamais partir d'une page blanche.**

- Identification du template le plus proche dans la Deliverable Factory
- Chargement : modèle, checklist, référentiels, exemple, plan d'actions type
- Recherche d'antécédents : missions similaires déjà réalisées
- Adaptation du template au contexte spécifique (secteur, juridiction, taille)

**Document maître** : [KHEPRA_DELIVERABLE_FACTORY.md](./KHEPRA_DELIVERABLE_FACTORY.md)

```
INPUT  → Méthodologie sélectionnée (étape 2)
QUERY  → KHEPRA Deliverable Factory §1-3 + Intellectual Capital (précédents)
OUTPUT → Template adapté prêt pour la production
```

### Étape 4 — Production

**Génération du livrable. L'IA et le consultant travaillent sur une base solide.**

- Application du System Master Prompt
- Rédaction / génération du contenu
- Application des 5 règles de génération KHEPRA
- Premier contrôle qualité par l'auteur

**Document maître** : [KHEPRA_SYSTEM_MASTER_PROMPT.md](./KHEPRA_SYSTEM_MASTER_PROMPT.md)

```
INPUT  → Template + Méthodologie + Textes applicables (étapes 1-2-3)
PROCESS → KHEPRA System Master Prompt + Rédaction
OUTPUT → Livrable complet, prêt pour contrôle qualité
```

### Étape 5 — Quality Controller

**Gatekeeper. Rien ne sort sans validation.**

- Contrôle réglementaire (30%) — exactitude des textes, dates, statuts
- Contrôle institutionnel (20%) — valeurs KHEPRA, ton, positionnement
- Contrôle rédactionnel (20%) — clarté, structure, absence d'erreurs
- Contrôle marketing (15%) — impact, différenciation
- Contrôle crédibilité (15%) — sources, références, autorité
- **Score ≥ 9,5/10 → Étape 6. Score < 9,5 → Correction → Retour Étape 4**

**Document maître** : [KHEPRA_QUALITY_CONTROLLER.md](./KHEPRA_QUALITY_CONTROLLER.md)

```
INPUT  → Livrable produit (étape 4)
CHECK  → Matrice 5 axes Quality Controller
OUTPUT → Score /10 + Rapport de contrôle → GO / NO GO
```

### Étape 6 — Knowledge Capture

**Capitalisation automatique. Chaque livrable enrichit le patrimoine.**

- Knowledge Capture (obligatoire) — fiche structurée YAML
- Case Study Draft (si mission significative) — étude de cas anonymisée
- Scoring KOS /100 — Exactitude, Conformité, Valeur Client, Réutilisabilité, Innovation
- Fiche de Capitalisation — Intellectual Capital System
- Retour d'Expérience — leçons apprises, bonnes pratiques
- Bloc Capitalisation KHEPRA — synthèse exécutive

**Documents maîtres** : [KHEPRA_INTELLECTUAL_CAPITAL.md](./KHEPRA_INTELLECTUAL_CAPITAL.md), [KHEPRA_QUALITY_CONTROLLER.md](./KHEPRA_QUALITY_CONTROLLER.md) §9

```
INPUT  → Livrable validé (étape 5)
PROCESS → Knowledge Capture + Case Study + Scoring + Fiche Capitalisation
OUTPUT → Connaissances structurées, prêtes pour intégration
```

### Étape 7 — Mise à jour KHEPRA

**Enrichissement du patrimoine. La boucle se referme.**

- Mise à jour du RAG — nouveaux textes, analyses, jurisprudences
- Mise à jour des Méthodologies — si la mission a révélé une amélioration
- Mise à jour des Templates — nouveaux modèles si nécessaire
- Alimentation de l'Intellectual Capital — fiches, études de cas, retours d'expérience
- Alimentation de la Thought Leadership — contenu premium pour le site
- Alimentation de la Competitive Intelligence — veille concurrentielle

```
INPUT  → Knowledge Captures + Case Studies + Scorings + Retours d'expérience
CYCLE  → RAG enrichi → Meilleures méthodologies → Templates plus précis
         → Prochaine mission bénéficie de toute l'expérience cumulée
OUTPUT → PATRIMOINE INTELLECTUEL KHEPRA ENRICHIE
```

### La Boucle de Rétroaction

Le Pipeline Fondamental n'est pas linéaire — c'est une **boucle d'amélioration continue** :

```
MISSION N   → RAG → Méthodologies → Templates → Production → QC → Capture → MàJ KHEPRA
                                                                              │
MISSION N+1 ← RAG (enrichi) ← Méthodologies (améliorées) ← Templates (affinés) ◄┘
```

**Chaque mission rend la suivante plus rapide, plus précise et plus qualitative.**

### 4.1 Matrice de Similarité

Pour évaluer si un précédent est suffisamment proche pour être réutilisé :

| Critère | Même | Proche | Différent |
|---------|------|--------|-----------|
| Secteur | Réutilisation directe | Adaptation légère | Nouveau contenu |
| Juridiction | Réutilisation directe | Vérifier spécificités locales | Nouveau contenu |
| Type de mission | Utiliser le template | Adapter le template le plus proche | Créer un nouveau template |
| Taille du client | Adapter l'échelle | Adapter | Nouveau contenu |

**Règle de décision** :
- Si au moins 3 critères sur 4 sont « Même » ou « Proche » → Réutilisation prioritaire, adaptation a minima
- Si 2 critères sur 4 sont « Même » ou « Proche » → Adaptation significative avec base existante
- Si moins de 2 critères → Nouveau contenu (mais toujours avec les templates standards de la Factory)

### 4.2 Bénéfices

La recherche d'antécédents garantit :
- **Cohérence** — Les livrables KHEPRA sont homogènes dans leur structure et leur qualité
- **Efficacité** — Pas de réinvention de la roue à chaque mission
- **Qualité** — Les améliorations sont cumulatives, pas redondantes
- **Traçabilité** — Chaque nouveau contenu sait de quel précédent il s'inspire

## RÈGLE OBLIGATOIRE N°5 — SCORING DE CHAQUE LIVRABLE

**Chaque livrable doit être noté selon 5 axes sur un score global de 100 points.**

### 5.1 Les 5 Axes du Scoring KOS

| Axe | Définition | Pondération | Score max |
|-----|-----------|-------------|-----------|
| **Exactitude** | Précision réglementaire, factualité, absence d'erreurs | 25% | 25 |
| **Conformité** | Alignement sur les exigences réglementaires et standards KHEPRA | 25% | 25 |
| **Valeur Client** | Utilité concrète, actionnabilité, retour sur investissement pour le client | 20% | 20 |
| **Réutilisabilité** | Capacité du livrable à servir de base pour des missions futures | 15% | 15 |
| **Innovation** | Originalité de l'approche, méthodes nouvelles, différenciation | 15% | 15 |
| **TOTAL** | | **100%** | **/100** |

### 5.2 Grille de Scoring Détaillée

#### Exactitude (/25)

| Score | Niveau | Critère |
|-------|--------|---------|
| 22-25 | Excellence | Zéro erreur réglementaire. Toutes les références vérifiées, sourcées, en vigueur. Aucune approximation. |
| 17-21 | Très bon | Une erreur mineure sans impact. Références correctes mais une imprécision. |
| 12-16 | Acceptable | Quelques imprécisions mineures. Corrections nécessaires avant réutilisation. |
| 6-11 | Insuffisant | Erreurs réglementaires significatives. Texte(s) abrogé(s) ou inexact(s). |
| 0-5 | Inacceptable | Erreurs graves. Contenu non livrable en l'état. |

#### Conformité (/25)

| Score | Niveau | Critère |
|-------|--------|---------|
| 22-25 | Excellence | Conformité totale au cadre réglementaire et aux standards KHEPRA. |
| 17-21 | Très bon | Conformité au cadre. Écarts mineurs sans conséquence. |
| 12-16 | Acceptable | Conformité partielle. Écarts à corriger. |
| 6-11 | Insuffisant | Non-conformité sur plusieurs points. |
| 0-5 | Inacceptable | Non-conformité majeure. Risque réglementaire ou réputationnel. |

#### Valeur Client (/20)

| Score | Niveau | Critère |
|-------|--------|---------|
| 18-20 | Excellence | Recommandations immédiatement actionnables. ROI clairement identifiable pour le client. |
| 14-17 | Très bon | Recommandations utiles et applicables. Valeur démontrée. |
| 10-13 | Acceptable | Recommandations pertinentes mais manquent de spécificité. |
| 5-9 | Insuffisant | Recommandations génériques, faiblement actionnables. |
| 0-4 | Inacceptable | Aucune recommandation concrète. Contenu purement descriptif. |

#### Réutilisabilité (/15)

| Score | Niveau | Critère |
|-------|--------|---------|
| 13-15 | Excellence | Livrable immédiatement réutilisable comme modèle. Structure, arguments et analyses transférables à d'autres secteurs/juridictions. |
| 10-12 | Très bon | Bonne réutilisabilité. Adaptations mineures nécessaires pour d'autres contextes. |
| 7-9 | Acceptable | Réutilisable avec adaptations significatives. |
| 4-6 | Insuffisant | Faiblement réutilisable. Trop spécifique à un contexte unique. |
| 0-3 | Inacceptable | Aucune valeur de réutilisation. Contenu jetable. |

#### Innovation (/15)

| Score | Niveau | Critère |
|-------|--------|---------|
| 13-15 | Excellence | Approche originale et différenciante. Méthode ou angle nouveau qui enrichit le patrimoine KHEPRA. |
| 10-12 | Très bon | Éléments d'innovation présents. Adaptation créative de méthodes connues. |
| 7-9 | Acceptable | Approche standard mais bien exécutée. |
| 4-6 | Insuffisant | Approche générique, sans différenciation. |
| 0-3 | Inacceptable | Copie ou reproduction non créditée. Aucune valeur ajoutée KHEPRA. |

### 5.3 Calcul du Score Global

```
Score Global = (Exactitude × 0,25) + (Conformité × 0,25) + (Valeur Client × 0,20) + (Réutilisabilité × 0,15) + (Innovation × 0,15)
```

### 5.4 Seuils de Décision

| Score | Décision | Action |
|-------|----------|--------|
| ≥ 85 | **EXCELLENCE** | Livrable approuvé. Intégration prioritaire dans le RAG et l'Intellectual Capital. |
| 70-84 | **BON** | Livrable approuvé. Intégration standard dans le RAG. |
| 55-69 | **ACCEPTABLE** | Corrections recommandées avant intégration. Révision dans les 30 jours. |
| 40-54 | **INSUFFISANT** | Corrections obligatoires. Ne pas intégrer avant mise à niveau. |
| < 40 | **INACCEPTABLE** | Refonte complète. Analyse racine obligatoire (Règle 3 §3 Methodology Update). |

### 5.5 Historique de Scoring

Tous les scores sont conservés dans l'Intellectual Capital System pour :
- Suivi de l'évolution de la qualité par type de mission
- Identification des axes d'amélioration transverses
- Benchmarking entre périodes
- Détection des Partners/consultants nécessitant un accompagnement

### 5.6 Complémentarité avec le Quality Controller

| Système | Rôle | Score | Usage |
|---------|------|-------|-------|
| **Quality Controller** | Gatekeeper — Publication autorisée ou bloquée | /10 (≥ 9,5) | Décision binaire publié/corrigé |
| **KOS Scoring** | Amélioration continue — Qualité intrinsèque et réutilisabilité | /100 | Pilotage long terme, capitalisation |

Les deux systèmes sont exécutés systématiquement et leurs résultats sont croisés :
- Un livrable peut passer le Quality Controller (sécurité réglementaire) mais avoir un faible score KOS (faible réutilisabilité)
- Un livrable avec un fort score KOS mais bloqué par le Quality Controller doit être corrigé

**À chaque interaction importante, produire un bloc interne « Capitalisation KHEPRA ».**

### 6.1 Définition d'une « Interaction Importante »

Sont considérées comme interactions importantes :

- Génération d'un livrable client
- Rédaction d'un article blog majeur
- Création d'un nouvel outil ou diagnostic
- Mise à jour significative d'un document KHEPRA
- Analyse réglementaire approfondie
- Proposition commerciale stratégique
- Réponse à une question réglementaire complexe

Ne sont PAS considérées comme interactions importantes :
- Corrections mineures (typos, liens)
- Réponses à des questions factuelles simples

### 9.3 Mise à Jour du KOS

Le KOS est un document vivant. Toute modification doit :
1. Être proposée par un Partner, motivée par des données d'exécution
2. Être examinée par le Partner Governance
3. Être validée par le Quality Controller (score ≥ 9,5)
4. Être approuvée par la Direction Générale
5. Être documentée dans l'historique des versions
6. Être communiquée à l'ensemble des Partners et agents IA

### 9.4 Calibration Annuelle

Les seuils de scoring (Règle 5) sont revus annuellement :
- Analyse des distributions de scores sur 12 mois
- Ajustement si nécessaire pour maintenir la discrimination
- Les seuils ne peuvent jamais être abaissés sans justification documentée
