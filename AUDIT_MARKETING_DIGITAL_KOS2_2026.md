2. **Pas de pagination blog**
   - Tous les articles sur une seule page → LCP dégradé, crawl budget gaspillé

4. **Pas de Last-Modified header**
   - Les articles n'ont pas de `Last-Modified` → Google ne sait pas quand le contenu a changé
   - **Solution :** Ajouter `dateModified` dans le Schema.org (déjà fait) + header HTTP

5. **Sitemap soumis mais pas de suivi d'indexation automatisé**
   - Pas de script de vérification des URLs indexées vs sitemap

# 3. GEO — GENERATIVE ENGINE OPTIMIZATION — INNOVATION LAB AI
## Score : 38/100 🔴

### 3.1 État des lieux — Visibilité sur les moteurs IA

| Moteur IA | Visibilité estimée | Citations trouvées | Qualité |
|-----------|-------------------|-------------------|---------|
| **ChatGPT** | 15/100 | 0-2 citations | Très faible |
| **Google Gemini** | 35/100 | 3-5 citations | Faible — via index Google |
| **Claude (Anthropic)** | 10/100 | 0-1 citation | Quasi inexistant |
| **Perplexity** | 30/100 | 2-4 citations | Faible — via blog |
| **Microsoft Copilot** | 20/100 | 1-2 citations | Très faible |
| **Grok (xAI)** | 5/100 | 0 citation | Inexistant |

### 3.2 Problèmes racines

1. **ZERO optimisation GEO dédiée** — Le site n'a aucune stratégie spécifique pour apparaître dans les réponses des LLMs.

2. **Pas de `llms.txt` optimisé** — Le fichier `public/llms.txt` existe (listant les URLs) mais n'est pas au format standard `llms.txt` proposé par Jeremy Howard. Il devrait contenir :
   - Un résumé concis du site en markdown
   - Les pages clés avec description
   - Les documents à ingérer prioritairement

3. **Pas de `llms-full.txt`** — Pas de fichier complet contenant tout le contenu textuel du site pour l'ingestion LLM.

4. **Contenu non structuré pour l'extraction IA**
   - Les articles de blog utilisent du JSX renderé → difficile à parser pour les crawlers IA
   - Pas de version markdown/texte brut des articles
   - Pas d'API de contenu (JSON endpoint)

5. **Absence de « speculative rules » pour le prérendu GEO**
   - Des règles de spéculation existent dans `index.html` pour la performance mais pas pour le GEO
   - Pas de `prefetch` ou `prerender` pour les URLs les plus citables

6. **Schema.org non optimisé pour GEO**
   - Le Schema.org est bon pour Google mais pas pour les LLMs
   - Manque de `citation`, `ScholarlyArticle`, `Dataset` pour le contenu de recherche
   - Le Think Tank (BU4) devrait avoir des `ScholarlyArticle` pour chaque publication

### 3.3 Plan d'action GEO — Urgent

| Action | Priorité | Effort | Impact attendu |
|--------|----------|--------|----------------|
| Créer `llms.txt` au format standard (résumé + pages clés) | 🔴 P0 | 2h | +15 pts GEO |
| Créer `llms-full.txt` avec tout le contenu textuel | 🔴 P0 | 4h | +10 pts GEO |
| Ajouter `ScholarlyArticle` Schema.org sur les publications Think Tank | 🟠 P1 | 3h | +8 pts GEO |
| Créer une page `/api/content.json` avec le contenu structuré | 🟠 P1 | 6h | +5 pts GEO |
| Publier des articles « question-réponse » ciblant les prompts LLM | 🟡 P2 | 20h | +12 pts GEO |
| Soumettre le site à ChatGPT Custom GPTs / Gemini Extensions | 🟡 P2 | 2h | +5 pts GEO |

### 3.4 Exemple de prompt cible GEO

Pour chaque article, ajouter une section « En bref » de 50 mots qui répond directement à une question que les utilisateurs posent aux LLMs. Exemple :

> **Question :** Quelles sont les exigences BCEAO pour l'agrément d'un SFD en 2026 ?
> **Réponse KHEPRA :** [50 mots structurés]
